# Bundled game references

The `qbx_fivem_data` crate's `docs` feature includes offline lookup tables for GTA V
control IDs and ped configuration flags. The ordinary linter build does not include
them. Reading a reference in an editor never makes a network request.

## Sources and provenance

- Controls: the [official Cfx controls reference](https://docs.fivem.net/docs/game-references/controls/),
  maintained in `citizenfx/fivem-docs` at `content/docs/game-references/controls.md`.
- Ped configuration flags: the enum in the [official SET_PED_CONFIG_FLAG source](https://github.com/citizenfx/natives/blob/master/PED/SetPedConfigFlag.md),
  maintained in `citizenfx/natives` at `PED/SetPedConfigFlag.md`.

The generated [source metadata](../crates/qbx_fivem_data/data/reference_sources.json)
records each upstream commit revision, its commit date, the immutable raw URL and
row count. The date is the source commit date, not a claim that every entry was
reverified on that day. Revisions are resolved for each source file rather than the
whole repository, so unrelated upstream commits do not change the bundle.

Control bindings are the documented QWERTY/Xbox defaults, not the player's current
bindings. Empty bindings stay empty; `(NONE)` is preserved when explicitly listed.
Markdown escapes and supported presentation tags are removed from display labels.

The ped enum cautions that names can be provisional and hash collisions may exist.
Original spellings and unknown hash placeholders are preserved. The current source
contains no per-flag behavioral prose, so every description is absent. We do not
turn symbolic names or speculative alias comments into invented explanations.

## Regeneration

```sh
cargo xtask references
cargo xtask references --pinned
```

The first command resolves the latest file-specific upstream commits, downloads
the files at those revisions, validates them, and writes only these files:

- `crates/qbx_fivem_data/data/controls.tsv`: ID, symbol, keyboard binding, controller binding.
- `crates/qbx_fivem_data/data/ped_config_flags.tsv`: ID, symbol, optional description (currently empty).
- `crates/qbx_fivem_data/data/reference_sources.json`: provenance for both tables.

`--pinned` downloads the recorded revisions and produces the same bytes, allowing
reproduction independently of later upstream changes. Both commands need network
access; consumers and normal tests use the checked-in tables. Native signatures
and native documentation are not regenerated by this task.

The generator checks headers/enum structure, IDs, symbol names, duplicate IDs and
unexpected markup. Both tables must be contiguous from zero, contain at least the
initial 361 controls and 464 flags, and never shrink below the checked-in count.
Downloads are size-limited, and both downloads are parsed and validated before any
output is replaced. An upstream schema change or intentional deletion requires a
reviewed generator change rather than silently publishing incomplete data.

## API and checks

With `features = ["docs"]`, `control(id)` and `ped_config_flag(id)` return small
copyable records borrowing static strings. `controls()` and `ped_config_flags()`
iterate the same tables for future reference browsing. `CONTROLS_SOURCE_URL` and
`PED_CONFIG_FLAGS_SOURCE_URL` identify the public documentation links.

```sh
cargo test --locked -p xtask
cargo test --locked -p qbx_fivem_data --features docs
```

Parser tests cover malformed/truncated sources, duplicates, the separate control
type table, escaped/HTML labels, blank bindings and unknown flag placeholders.
Data tests cover representative IDs, exact source spellings, missing descriptions,
complete ordering and lookup/iteration round trips.
